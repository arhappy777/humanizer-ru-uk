# Эталонный корпус

Проверка чувствительности и ложных срабатываний офлайн-аудитора. Это мера качества правил, а не детектор авторства.

## Структура

- `ai/` — посты в типовом ИИ-стиле, входят в репозиторий. Десять постов, от грубых (клише, чат-артефакты, кальки) до тонких: в `ru-05-subtle-rhythm.txt` и `uk-03-subtle.txt` нет ни одного словесного клише, их должны ловить только структурные правила.
- `human/` — реальные человеческие посты. В репозиторий не входят (`.gitignore`) — положите сюда свои: один пост, один файл `.txt` в UTF-8. Без человеческого корпуса нельзя измерить главное: сколько ложных флагов правила вешают на живой текст.

## Запуск

```bash
python scripts/eval_corpus.py
python scripts/eval_corpus.py --format json
```

## Базовая линия ИИ-корпуса (v0.3.2)

| Метрика | Значение |
|---|---|
| Постов поймано хотя бы одним флагом | 10 из 10 |
| Среднее флагов на пост | 4.3 (P0 0.2, P1 2.0, P2 2.1) |
| Постов с P1-или-строже | 60% |
| Частые коды | R01, S13, S07, S05, S06, S08, S20, U08 |

«Тонкие» посты без клише набирают только P2-флаги (S20 ровный ритм, S21 рубленые фразы, S26 тире, S14/S15) — это ожидаемо: словаря они не касаются.

## Как интерпретировать

- Регресс правил виден по падению среднего числа флагов на `ai/` при том же корпусе.
- Ложные срабатывания меряются на `human/`: если больше ~20% ваших реальных постов получают P1-или-строже, правила из top_codes человеческого отчёта стоит ослаблять.
- Пороги структурных правил (ритм, тире, хештеги) калибруются именно по человеческому корпусу, не по ИИ-стороне.

## Оговорки

- ИИ-сторона корпуса написана намеренно типовой; свежие модели могут писать иначе — корпус стоит пополнять реальными генерациями.
- Отсутствие флагов не доказывает, что текст написал человек, наличие — что модель.
